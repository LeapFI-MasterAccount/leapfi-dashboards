Sign up identity first.
Then hang the company off it.

The clean-start order for standing up Microsoft Entra ID and the Azure boundary. Identity is the plane everything else attaches to, so it goes first, then endpoints, source and CI, and the product. Everything must finish and freeze before the ~Sept 1 SOC 2 observation window opens, because a Type II report attests controls that operated over the whole window.

1
Sign up the Microsoft tenantWk 1▸

Create a fresh Microsoft 365 / Entra ID tenant and verify the leapfi.ai custom domain. Enroll in Microsoft for Startups (enterprise account manager + $100K+ Azure credits) so hosting, AVD compute, and Azure OpenAI run against credits.

Licensing: baseline M365 Business Premium is free via the program; upgrade key users to E5 (~$57/user/mo) for highest protection + unified audit. GitHub Enterprise is free via the program too.

2
Establish Entra ID as the single identity planeWk 1▸

Entra ID becomes the one place identity lives: SSO, MFA, Conditional Access, RBAC, SCIM. This is the CC6 access spine and the top SOC 2 evidence source.

Create a global admin plus break-glass emergency accounts; apply least-privilege admin roles. Define the joiner / mover / leaver process now, before users exist.

SSORBACSCIMLeapFI-owned control (CC6)
3
Enforce MFA + Conditional Access baselineWk 1▸

Require MFA for everyone. Conditional Access blocks unmanaged / non-compliant devices from reaching corporate or customer data. These are controls LeapFI owns and evidences (not inherited from the vendor).

MFAConditional AccessLeapFI-owned + evidenced
4
Managed cloud desktops under IntuneWk 1–2▸

Staff work in Azure Virtual Desktop (AVD): consumption-based, credit-eligible, Entra-joined + Intune-managed, so corporate/customer data never rests on a laptop. Dan and Adam run company-owned Intune-managed physical machines. Then decommission local storage.

Windows 365 Cloud PC is simpler but a fixed, non-credit-eligible subscription; use it only where predictability beats credit savings.

Azure Virtual DesktopIntune baselinesNo data on laptops
5
GitHub Enterprise + SSO / SCIMWk 2▸

Stand up GitHub Enterprise with SAML SSO, SCIM, audit log, branch protection / rulesets, secret scanning. This is the change-management evidence. Structure as two orgs: Org A (engine + product, in SOC 2 scope, no Claude connection) and Org B (business/ops, Claude read-only). Separate orgs make the engine unreachable by construction.

SAML SSOBranch protectionSecret scanningTwo-org boundary
6
Azure subscription + product boundaryWk 2–3▸

Stand up the Azure hosting foundation (SOC 1/2/3, ISO 27001/17/18) and re-platform OnSide into it. Model layer = Azure OpenAI (in-boundary, not used to train, region-pinnable) with Claude via Azure Foundry for Claude-grade reasoning. Purview DLP reinforces the no-NPI boundary. Retire the local Docling/Ollama pipeline. Hosting + AVD + Azure OpenAI are Azure consumption, covered by credits.

Azure hostingAzure OpenAIFoundry-ClaudePurview DLP
7
Adopt Claude Team as the company assistantWk 3▸

Claude Team is the company standard and is SOC 2-compliant (Anthropic SOC 2 I & II, ISO 27001 / 42001; business data training-excluded by default), a certified vendor in the data room. SSO is available on Team; layer on Enterprise controls (audit logs, SCIM, custom retention) later if the auditor wants tool-level access evidence.

Freeze config before ~Sept 1~Sep 1▸

Freeze the configuration; the managed SOC 2 partner starts the Type II observation window. Migrating mid-window breaks the report, so the whole clean start finishes and freezes first. Map every platform to the partner's readiness checklist before the freeze.
